# 1.Базовые принципы в anpoint

- Использовать сущ. во мнж. числе

```
/users - правильно
/getUsers - неправильно
```

- Использовать вложенность для связи ресурсов, пример:

```
/users/{userId}/orders - получение пользовательских заказов
```

- Использовать kebab case (для сложных названий ) (начало с маленькой второе слово с большой)

```
/items/{userId}/oreders
```

- Избегать лишних слов (не добавлять глаголов, если этого не требуется)

```
/products, а не /getproducts
```

# 2. Как выбрать http метод

## 1.Create => POST => CreateNewResurs используется, когда у ресурса нет ID (за исключением иерархической вложености)

## 2.Получить => Get => возращает данные, не изменяя рес., а так же содержит query параметры

- все, что после '?' содержит имя и последующий знак = являяется query параметром,
- если query параметр содержит '{}' значит он является json форматом

```
GET/users?id=2
GET/users?filters={status:"active"}
```

## 3.Обновить(изменить) => PUT || PATCH => обновляет сущ. ресурс

- PUT - полная замена
- PATCH - частичное обновление

```
PUT/users/{usersId}/avatar
PATCH/users{usersId}/settings
```

## 4. Удалить => DELETE => удаляет или помечает как удаленный рес. по id

```
Delete/items/{itemId}
```

# 3. Когда использовать query парамтеры

- Нужно фильтровать, сортировать или искать по данным

## 1.Передача не обязательных параметров, например: ключ сортировки

```
?sortKey = 1 - сортировка по ключам
?sort = ASC - сортировка по буквам
?sort = DESC

GET/products?name = DESC
(сортировка по имени, за счет "name". Было бы price,
была бы сортировка по цене, типа, price = ABC)

GET/products?page=1 & limit=50
(page(страница) & limit(кол-во элементов на стр.) - ключевые слова)
```

## 2. Передача данных, которые не являются частью индетификатором(ID) рес.

```
GET/search?q=Android (поиск по всему сайту)
```

# 4. Когда использовать PATH параметры

- PATH параметры - это часть url в {}

```
POST/items/{itemId}/upload
```

## Когда писать

- Необходимо указать обязательный индефикатор ресурса, например в методах: POST, PATCH, PUT, DELETE
- Реализации иерархической связи ресурсов

```
POST/users/{userId}/photo - подгрузка фото
```

# 5. Когда использовать body (тело запроса)

## 1.В случае передачи данных, которые требуют шифрования

## 2.При передачи большого кол-во данных (массив||объект)

## 3.В методах: POST, PUT, PATCH

```
body представляет из себя json объект, приведенный к строковому представлению
```
